2. Signal flow per voice

Wavesample (normalised)→ Oscillator 1 + 2
virtual DAC clock, 8 bit→ Mix→ 4-pole ladder low-pass
cutoff ← filter envelope, keytrack→ VCA
← amp envelope→ Level→ Sum of all voices × volume→ Soft clip

8-bit emulation

The Mirage changes pitch by varying the clock of its D/A converter. The plugin reproduces this: each oscillator runs a virtual DAC clock at RATE × pitch ratio. On every tick a new value is read, rounded to 8 bits (round(x·127)/127) and held until the next tick (zero-order hold). There is no interpolation and no anti-aliasing filter before the low-pass. This creates the typical aliasing and quantisation grain.

DAC ticks per output sample = RATE · 2^(semitones/12) / host sample rate
Source samples per DAC tick = file sample rate / RATE
Semitones = note − root + 12 · (Octave + Master Octave) + Coarse + Fine/100 + Tune/100 + Bend + LFO (+ Detune on osc 2)

With 8-BIT off, playback is linearly interpolated without quantisation.

Filter

Zero-delay-feedback ladder filter (4 × TPT one-pole low-pass) with feedback. The saturation at the filter input is modelled loosely on the Curtis CEM3328. Bass loss at high resonance is partly compensated.

Octaves = Cutoff/99 · 9.5 + Keytrack/4 · (note − 60)/12 + filter envelope · 9.5
fc      = 30 Hz · 2^Octaves        (limited to 20 Hz … 0.45 · sample rate)
k       = 3.96 · Reso/40           (self-oscillation near k = 4)

Filter coefficients are updated every 16 samples.

Envelopes

Stages: attack (linear) → peak, decay (exponential) → sustain, release (exponential) → 0. Sustain is relative to the peak.

Time(v)  = 1.5 ms · 20000^(v/99)                 v = 0…99  →  1.5 ms … 30 s
Attack   = Time(ATT) · (1 − 0.95 · ATTVEL/99 · velocity)
Peak     = PEAK/99 · (1 − PKVEL/99 · (1 − velocity))
Decay    = Time(DEC) · 2^(−(note − 60)/12 · DECKEY/99)
Sustain  = Peak · SUS/99 · (1 − SUSKEY/99 · clamp((note − 36)/60, 0, 1))
Release  = Time(REL) · (1 − 0.9 · RELVEL/99 · release velocity)

Oscillator mix and LFO

Mix      = clamp(MIX/99 + MIXVEL/99 · (velocity − 0.5), 0, 1)
Output   = Osc1 · (1 − Mix) + Osc2 · Mix
Detune   = DETUNE/99 · 0.5 semitones (osc 2 only)
LFO      = triangle, 0.1 Hz · 200^(SPEED/99)
Depth    = (min(99, DEPTH + mod wheel · 99)/99)² · 3 semitones

Output

Gain   = 0.9 · (VOLUME/99)²
Out    = tanh approximation(sum · Gain)

Wheels

The audio thread stores pitch bend and CC1 in atomic variables. The interface reads them at 30 Hz and moves the wheels along. While you hold a wheel with the mouse, the mouse takes priority. Mouse movements enter the same input as MIDI (MidiMessageCollector).

5. Storage

DAW project

The plugin state is stored as XML (binary wrapped):

<MiracleDSPState version="1" editPanelOpen="0">
  <PARAMS> … all parameters … </PARAMS>
  <Folders lower="/path/to/folder" upper="/path/to/folder"
           lowerSound="Subfolder/File.wav" upperSound="File.wav"/>
  <Programs currentLower="0" currentUpper="2">
    <Program half="0" slot="0" cutoff="0.70" … />   <!-- normalised values 0…1 -->
  </Programs>
</MiracleDSPState>

The sound is found again by its path relative to the folder, so the selection survives added files. If the file is missing, the first sound is selected. If the folder is missing, the path stays stored and the built-in waveform plays.

Global preferences

~/Library/Application Support/MIRACLE DSP/MIRACLE DSP.settings stores the most recently used folders and sounds (lastLowerFolder, lastLowerSound, lastUpperFolder, lastUpperSound) and editPanelOpen. New instances load these automatically; a saved project state takes priority.

Package ID: com.ess76.miracledsp.pkg. The postinstall script removes copies with the same name from ~/Library/Audio/Plug-Ins, so the plugin does not appear twice, and resets the AU cache (AudioComponentRegistrar). The bundles are ad-hoc signed; package and plugins are not notarised by Apple. That is why Gatekeeper asks on first opening.

To verify the installation:

pkgutil --pkg-info com.ess76.miracledsp.pkg
auval -v aumu Mdsp Ess7

7. Building from source

pip3 install --user cmake
git clone --depth 1 --branch 8.0.10 https://github.com/juce-framework/JUCE.git ~/Developer/JUCE
export PATH="$HOME/Library/Python/3.9/bin:$PATH"
cmake -S MiracleDSP -B build -DCMAKE_BUILD_TYPE=Release \
      "-DCMAKE_OSX_ARCHITECTURES=arm64;x86_64" -DCMAKE_OSX_DEPLOYMENT_TARGET=11.0
cmake --build build -j8

The build copies the plugins to ~/Library/Audio/Plug-Ins. Installer and DMG are created by Release/build_installer.sh [build folder]; the default is ~/Developer/MiracleDSP-build-universal.

Project structure

FileContents
Source/Params.hParameter catalogue with original-style numbers, ranges, defaults
Source/MiracleEngine.*Voice management, oscillators with DAC emulation, ladder filter, envelopes, LFO, MIDI
Source/SampleBank.*Folder scan, audio file loading, root note and loop detection
Source/PluginProcessor.*Plugin interface, programs, save/load, thread-safe sound change
Source/PluginEditor.*Interface: display, keypad logic, disk tray, pitch and mod wheels, EDIT PANEL with faders, waveform, keyboard

Thread safety: a sound change creates a new, reference-counted SampleBank object. The audio thread takes it over with a try-lock. The message thread frees old objects once no voice uses them. Files are never loaded on the audio thread. The mouse wheels go through MidiMessageCollector, which locks briefly internally.

8. Differences from the original

  • No sampling from an audio input, no Mirage disk format, no sequencer.
  • One sound per half instead of up to 8 wavesamples with keyboard zones.
  • Up to 16 instead of 8 voices; samples up to 30 s instead of 64 KB per half.
  • Parameter numbers are based on the original but are not identical.
  • The keypad column “SOUND” (sound and octave) and HALF/LOAD replace the sequencer and sample keys of the original. The EDIT PANEL is an addition with no hardware counterpart.
