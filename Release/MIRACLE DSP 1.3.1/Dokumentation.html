2. Signalfluss pro Stimme

Wavesample (normalisiert)→ Oszillator 1 + 2
virtueller DAC-Takt, 8 Bit→ Mix→ 4-Pol-Ladder-Tiefpass
Cutoff ← Filter-Hüllkurve, Keytrack→ VCA
← Amp-Hüllkurve→ Level→ Summe aller Stimmen × Volume→ Soft-Clip

8-Bit-Emulation

Der Mirage verändert die Tonhöhe, indem er den Takt seines D/A-Wandlers variiert. Das Plugin bildet das nach: Jeder Oszillator führt einen virtuellen DAC-Takt mit RATE × Tonhöhenverhältnis. Bei jedem Takt wird ein neuer Wert gelesen, auf 8 Bit gerundet (round(x·127)/127) und bis zum nächsten Takt gehalten (Zero-Order-Hold). Es gibt keine Interpolation und kein Anti-Aliasing-Filter vor dem Tiefpass. Daraus entstehen das typische Aliasing und die Quantisierungskörnung.

DAC-Takte pro Ausgabesample = RATE · 2^(Halbtöne/12) / Host-Samplerate
Quellsamples pro DAC-Takt   = Datei-Samplerate / RATE
Halbtöne = Note − Grundton + 12 · (Octave + Master-Octave) + Coarse + Fine/100 + Tune/100 + Bend + LFO (+ Detune bei Osc 2)

Mit 8-BIT = aus wird linear interpoliert ohne Quantisierung.

Filter

Zero-Delay-Feedback-Ladder-Filter (4 × TPT-Einpol-Tiefpass) mit Rückkopplung. Die Sättigung am Filtereingang lehnt sich an den Curtis CEM3328 an. Bassverlust bei hoher Resonanz wird teilweise ausgeglichen.

Oktaven = Cutoff/99 · 9,5 + Keytrack/4 · (Note − 60)/12 + Filter-Hüllkurve · 9,5
fc      = 30 Hz · 2^Oktaven        (begrenzt auf 20 Hz … 0,45 · Samplerate)
k       = 3,96 · Reso/40           (Selbstoszillation nahe k = 4)

Die Filterkoeffizienten werden alle 16 Samples aktualisiert.

Hüllkurven

Phasen: Attack (linear) → Peak, Decay (exponentiell) → Sustain, Release (exponentiell) → 0. Sustain ist relativ zum Peak.

Zeit(v)  = 1,5 ms · 20000^(v/99)                 v = 0…99  →  1,5 ms … 30 s
Attack   = Zeit(ATT) · (1 − 0,95 · ATTVEL/99 · Velocity)
Peak     = PEAK/99 · (1 − PKVEL/99 · (1 − Velocity))
Decay    = Zeit(DEC) · 2^(−(Note − 60)/12 · DECKEY/99)
Sustain  = Peak · SUS/99 · (1 − SUSKEY/99 · clamp((Note − 36)/60, 0, 1))
Release  = Zeit(REL) · (1 − 0,9 · RELVEL/99 · Release-Velocity)

Oszillator-Mix und LFO

Mix      = clamp(MIX/99 + MIXVEL/99 · (Velocity − 0,5), 0, 1)
Ausgang  = Osc1 · (1 − Mix) + Osc2 · Mix
Detune   = DETUNE/99 · 0,5 Halbtöne (nur Osc 2)
LFO      = Dreieck, 0,1 Hz · 200^(SPEED/99)
Tiefe    = (min(99, DEPTH + Modrad · 99)/99)² · 3 Halbtöne

Ausgang

Gain   = 0,9 · (VOLUME/99)²
Out    = tanh-Näherung(Summe · Gain)

Räder

Der Audio-Thread legt Pitchbend und CC1 in atomaren Variablen ab. Die Oberfläche liest sie mit 30 Hz und bewegt die Räder mit. Während du ein Rad mit der Maus hältst, hat die Maus Vorrang. Maus-Bewegungen laufen als MIDI in denselben Eingang (MidiMessageCollector).

5. Speicherung

DAW-Projekt

Der Plugin-Zustand wird als XML (binär gekapselt) gespeichert:

<MiracleDSPState version="1" editPanelOpen="0">
  <PARAMS> … alle Parameter … </PARAMS>
  <Folders lower="/Pfad/zum/Ordner" upper="/Pfad/zum/Ordner"
           lowerSound="Unterordner/Datei.wav" upperSound="Datei.wav"/>
  <Programs currentLower="0" currentUpper="2">
    <Program half="0" slot="0" cutoff="0.70" … />   <!-- normalisierte Werte 0…1 -->
  </Programs>
</MiracleDSPState>

Der Sound wird über den Pfad relativ zum Ordner wiedergefunden. So bleibt die Auswahl erhalten, auch wenn Dateien hinzukommen. Fehlt die Datei, wird der erste Sound gewählt. Fehlt der Ordner, bleibt der Pfad gespeichert und die eingebaute Wellenform spielt.

Globale Voreinstellung

~/Library/Application Support/MIRACLE DSP/MIRACLE DSP.settings speichert zuletzt benutzte Ordner und Sounds (lastLowerFolder, lastLowerSound, lastUpperFolder, lastUpperSound) sowie editPanelOpen. Neue Instanzen laden diese automatisch; ein gespeicherter Projektzustand hat Vorrang.

6. Installation (technisch)

DateiZiel
MIRACLE DSP.component/Library/Audio/Plug-Ins/Components/
MIRACLE DSP.vst3/Library/Audio/Plug-Ins/VST3/
MIRACLE DSP.app/Applications/

Paket-ID: com.ess76.miracledsp.pkg. Das Postinstall-Skript entfernt gleichnamige Kopien aus ~/Library/Audio/Plug-Ins, damit das Plugin nicht doppelt erscheint, und setzt den AU-Cache zurück (AudioComponentRegistrar). Die Bundles sind ad-hoc signiert, Paket und Plugins sind nicht von Apple notarisiert. Deshalb fragt Gatekeeper beim ersten Öffnen nach.

Installation prüfen:

pkgutil --pkg-info com.ess76.miracledsp.pkg
auval -v aumu Mdsp Ess7

7. Aus dem Quellcode bauen

pip3 install --user cmake
git clone --depth 1 --branch 8.0.10 https://github.com/juce-framework/JUCE.git ~/Developer/JUCE
export PATH="$HOME/Library/Python/3.9/bin:$PATH"
cmake -S MiracleDSP -B build -DCMAKE_BUILD_TYPE=Release \
      "-DCMAKE_OSX_ARCHITECTURES=arm64;x86_64" -DCMAKE_OSX_DEPLOYMENT_TARGET=11.0
cmake --build build -j8

Der Build kopiert die Plugins nach ~/Library/Audio/Plug-Ins. Installer und DMG erzeugt Release/build_installer.sh [Build-Ordner]; Standard ist ~/Developer/MiracleDSP-build-universal.

Projektstruktur

DateiInhalt

Thread-Sicherheit: Ein Sound-Wechsel erzeugt ein neues, referenzgezähltes SampleBank-Objekt. Der Audio-Thread übernimmt es per Try-Lock. Alte Objekte gibt der Message-Thread frei, sobald keine Stimme sie mehr nutzt. Dateien werden nie im Audio-Thread geladen. Die Maus-Räder laufen über MidiMessageCollector, der intern kurz sperrt.

8. Abweichungen vom Original

  • Kein Sampling über einen Audioeingang, kein Mirage-Diskettenformat, kein Sequencer.
  • Ein Sound pro Hälfte statt bis zu 8 Wavesamples mit Tastaturzonen.
  • Bis zu 16 statt 8 Stimmen; Samples bis 30 s statt 64 KB pro Hälfte.
  • Parameternummern orientieren sich am Original, sind aber nicht identisch.
  • Keypad-Spalte „SOUND“ (Sound und Oktave) und HALF/LOAD ersetzen Sequencer- und Sample-Tasten des Originals. Das EDIT PANEL ist eine Ergänzung ohne Hardware-Vorbild.
